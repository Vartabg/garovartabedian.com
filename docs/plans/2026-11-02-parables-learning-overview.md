# Parables: a map for reading

## Purpose and decisions

A reader should be able to see what is in the room, notice which Gospels contain an account, find a title or reference, and open the existing side-by-side readings. The current page is a long sequence of large identical rows; its four Gospel categories and hundreds of early-writing selections cannot be surveyed together.

Previously accepted: Gospels first; Gospel accounts side by side; early-writing comparisons and their separate collection behind folds; explicit outside-the-canon labels. Not chosen: one telling at a time in tabs. The user now says the layout does not support learning and a big-picture overview. They have not chosen a specific new visual design.

Considered: (1) shorten the existing rows, which helps scanning but does not reveal coverage; (2) a compact source map with groups and a searchable index, retaining the existing readings; (3) an interpretive thematic map, which would require editorial classification. Choose (2): categories and Gospel presence are already in the data, so the overview does not invent scholarly claims.

## Design

- After the introduction, offer a compact all-groups summary with counts for stories, short sayings, Matthew/Mark/Luke figures, John figures, and selections from early writings outside the canon. The four Gospel groups show counts of entries containing each Gospel account in this room; the outside-canon collection has no Gospel-account counts. Labels describe the existing groups, not a universal or complete classification. Counts are entry counts, not unique parables or writings.
- Default the index to stories. A compact semantic table shows titles and four Matthew/Mark/Luke/John columns, derived only from each account's parsed book; each cell has a screen-reader present/absent/unknown label. A blank indicates no account represented here, not absence of other parallels or scholarly consensus. If any account cannot be parsed or names an unexpected book, otherwise absent cells are unknown rather than negative. Column and row headers, selected group state, a live result count and explicit zero results convey state; 320px and 200% zoom must not cause page overflow.
- Group buttons switch the index. Search is across all groups and matches titles, references, and available writing/speaker names; results retain group labels. Clearing search restores the chosen group. The early-writing index groups entries by named writing, showing counts and using native expandable groups, with search revealing matching entries. Thomas and James are separately and plainly labeled outside the canon. A zero-results message is explicit.
- An index title is a real hash link to the existing entry. Activating it opens and scrolls to that entry, including opening the early-writing fold; repeated activation of an unchanged hash calls the same open path and adds no history entry; another destination adds at most one. Direct hashes, browser back/forward, and Find use the existing hash/event mechanism. Focus moves to the entry control, reduced motion is respected, and every expanded entry offers a link back to the overview, which focuses the overview. A history destination with no recognized hash leaves the opened state alone and lets the browser restore scroll. Existing no-JS source-link fallback, full texts, speaker labels, attribution, notes and comparisons remain unchanged. Existing JavaScript-controlled readings do not newly become no-JS readings. Overview controls become active once hydrated, preventing early clicks from silently navigating without opening the entry.
- The overview inherits the Jesus world's typography and color tokens. Use compact editorial table rows and simple rules; no new graphics or invented summaries. On small screens the matrix must remain legible and not cause horizontal page overflow; early-writing group controls and results must be keyboard accessible.

## Scope and checks

Likely files: `src/app/jesus/parables/ParablesRoom.tsx`, an isolated overview component/data helper if useful, `src/app/styles/jesus.css`, focused tests, and this plan/review. Reuse typed data from the room; do not change source records or passage content. The index is a navigation aid; preserve the existing no-JavaScript source links and explain that the interactive overview requires JavaScript.

Search normalizes case, punctuation and spacing and covers titles, Gospel names and abbreviations and each account's ref, setting, explanation and called reference; early entries add their writing, locator and speaker. Recognizable Gospel references match the book and chapter and intersect actual verse ranges; results identify the matching account, setting, explanation or verse calling it a parable. Group early entries by the existing exact work name, with Thomas and James each added once; search results retain their outside-the-canon heading. The table explains ●, — and ? visibly; at narrow widths and 200% text size, a labeled keyboard-scrollable table region keeps its columns legible. Test category counts and source markers against actual accounts, including invalid references; search across categories, no-results and clear; early-writing grouped expansion and entry linking; repeated hashes, direct hashes, Find and history; keyboard focus, no-JS source links, loading failure and retry; desktop and 320/390px at enlarged text in both schemes. Inspect at 200% browser zoom where feasible, including titles, cells and controls. Inspect real rendered states and verify source excerpts still open. Run project lint, typecheck, tests, build and a11y. Preserve long text inside existing panels.
